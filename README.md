# Stashwell

Stashwell is a web media downloader and local resource library with a Chrome side panel. The first manual **Scan page** starts collection and automatic resource updates for that tab while the panel is visible. Automatic updates need no extra control after that first scan; **Scan again** performs an additional manual refresh. Close Stashwell to stop automatic updates. Unscanned tabs never collect automatically. Switching to a previously scanned tab resumes its updates within the same panel session and origin. The web library and extension use the same archive format.

## Workspace

- `apps/web` — Next.js library dashboard, using Turbopack for development.
- `apps/extension` — CSP-compatible Manifest V3 side panel, sharing the React library UI with the Next.js dashboard.
- `packages/core` — shared resource types, archive helpers, and local URL heuristics.
- `packages/library-ui` — shared Drive-inspired library interface and storage adapters.

The repo uses pnpm workspaces and Turborepo. The Next.js projects use Turbopack in development.

## Run locally

```sh
pnpm install
pnpm dev
```

The web library runs at `http://localhost:3000`; the extension preview runs at `http://localhost:3001`.

## Load the Chrome extension

```sh
pnpm --filter @stashwell/extension build
```

In Chrome, open `chrome://extensions`, turn on Developer mode, choose **Load unpacked**, and select `apps/extension/out`. The extension requires Chrome 114 or later for the Side Panel API.

The extension uses a separate static React bundle because Manifest V3 blocks inline scripts generated by Next.js. Both surfaces use the same shared library UI and adapters.

Click Stashwell's toolbar icon to open the side panel, and click it again to close the panel. Choose **Scan page** to collect the active webpage. The panel follows the active tab: a previously scanned URL shows its saved collection, and a new URL shows the first-scan view. On a new tab or after navigating to another origin, choose **Scan page** again; Chrome may ask to allow access to that website. The extension uses `tabs` to read the active tab's address, title, favicon, and loading state; `activeTab` still provides temporary access when the toolbar icon is invoked. It also uses `scripting`, `sidePanel`, `storage`, `unlimitedStorage`, `downloads`, and `alarms`. It has no required host permission. Optional HTTP/HTTPS grants are requested for manual scans and selected file actions; a grant alone never enables automatic collection. A packaged resource watcher runs only on a manually scanned, active tab while its panel connection is open. It observes resource-related changes, fonts, loads, and accessible shadow roots; it stops when hidden, inactive, or closed. Security checks remain local.

## Manage your library

The installed extension and website share the approved A2 (Twin fold) logo from `apps/extension/public/icons/stashwell.svg`: two blue angular ribbon paths with an open diagonal seam, a transparent background, and no surrounding square. The extension's panel header and favicon use this SVG. Run `pnpm generate:extension-icons` for its transparent 16/32/48/128px toolbar and extension-manager icons. Run `pnpm generate:web-brand` to update the website's shared `/icons/stashwell.svg` and reusable blue/white SVG and PNG logos while preserving extension and store assets. `pnpm generate:brand` intentionally updates website, extension, and store promotional assets together; use it only for an approved update across those surfaces.

Reusable A2 SVG and transparent PNG logos, including white variants for dark backgrounds and outlined Geist wordmarks, are in `apps/web/public/brand/`. Landing-page navigation, previews, the closing call to action, setup/legal pages, the web library and demos, and the website favicon use the shared A2 web mark. The mark represents finds tucked away for later. The application name is written **Stashwell**. Existing libraries, bookmarks, deleted-item exclusions, and download history retain their original storage keys for upgrade compatibility. New JSON backups use `stashwell-library`; backups from the previous application name remain importable.

The scan button follows the active tab and shows its favicon, with a globe fallback. Amber **Scan page** means the current document needs a scan; blue **Scan again** means it was scanned. An unscanned URL shows a first-scan view even when the library contains other pages; the Source page menu can still open those older captures. Before the first scan, the Source page line explains that scanning enables automatic updates. The compact header has no automatic-update status row or Pause/Resume controls. Authorization lives only in memory for that tab and origin during the panel session. Library management and deleted-page exclusions hold automatic updates; background refreshes never restore deleted resources. Manual scans and imports can restore exclusions.

Open the menu at the right of **Scan page** and choose **Manage**. Search captured pages, select pages to delete, or open a page to select and delete individual items. **Undo** restores the most recent deletion while the library remains open. Deleted pages and items remain deleted when tabs change or the panel reopens. An explicit **Scan page** action restores resources from the current page; importing a page also restores it.

Choose **Saved items** from the same menu to browse bookmarks across captured pages. Images, Icons, Fonts, Video & audio, Links, Files, and **All saved** all stay filtered to bookmarks. Source-page filtering, selection, and bulk actions use that same saved scope. Choose **All resources** or **Back to library** to return to the full collection.

Browser verification: build the extension, then run `node scripts/verify-library-management.mjs`. It uses an isolated Brave profile to check saved filtering, deletion and Undo, failed writes, automatic rescan suppression, persistence, and responsive management controls. Set `STASHWELL_WEB_URL` to a running Next.js library to include the shared web interface.

## Download video and audio

Scan a page, open **Video & audio**, and use a card's dots menu to download direct video or audio files. The scanner does not extract YouTube videos. YouTube watch, Shorts, and embed URLs found on a page can still appear in **Links** with Copy URL.

Previously saved YouTube video cards remain in the library until deleted or their source page is rescanned. They show a static thumbnail and offer Copy URL. YouTube video/audio downloading is not offered.

Direct media downloads use the browser download manager. The bottom download bar shows bytes received, a percentage when known, Cancel, completed files, and failures. Expand it to see earlier downloads; completed files can be shown in their folder. Started file transfers continue when the sidebar closes, and their state restores when it reopens. The bar remains visible inside a preview modal.

If website access was withheld, the download bar shows **Allow access & retry** for the media host. Denying file-host access leaves the action available to retry. Scan page may request access only to the active website; an existing site grant lets it continue without a new prompt. Host restrictions and unsupported stream playlists are reported separately. After rebuilding, reload Stashwell on the browser's extensions page and reopen its sidebar to load the new controls and manifest.

Verification: `node scripts/verify-image-actions.mjs --download-check` checks direct file bytes, progress, cancellation, reload persistence, native website-access requests and simulated denial/grant/retry. It also checks that a direct video file appears in **Video & audio** while YouTube watch and Shorts URLs remain links.

## Download files and selected resources

Files with uncommon extensions are collected alongside common documents and media. In the extension, a single direct HTTP or HTTPS file download uses Chrome's download manager, which keeps the source filename from the server when available. Direct file resources are saved as received, without converting their format. Image and icon actions still validate supported preview formats. Links and page entries download as `.url` shortcuts.

Icon and image menus and sidebar previews include a **Download format** selector. Icons offer Original, SVG, PNG, JPEG, and WebP; images offer Original, PNG, JPEG, and WebP. Original is the default. SVG keeps vector icons as vectors and embeds raster icons as images. JPEG uses a white background for transparency. Converting an animated image saves one frame; Original preserves its source format.

Select resources and choose **Download as ZIP** to package them, including files with uncommon formats. The bulk actions panel has separate **Icon format** and **Image format** selectors; other files keep their original bytes. With Original selected, the ZIP uses source filenames when supplied by the server. It gives duplicate names a suffix and lists unavailable entries in `stashwell-skipped.txt`. ZIP creation is limited to 256 MB of included file data in this browser session. The web dashboard also limits an individual fetched download to 256 MB and requires the file host to allow browser cross-origin fetching. Protected links, expired addresses, and streaming playlists may require downloading from the source site.

Verification: build the extension, then run `node scripts/verify-image-actions.mjs --format-check` to check converted file bytes, dimensions, transparency, icon SVGs, single and mixed bulk downloads, and responsive controls. Set `STASHWELL_WEB_URL` to a running web library to include web format controls and a converted ZIP.

## Send selected assets to design applications

In the installed extension, select images or icons and choose **Send to app** in the selection bar. Choose Figma, Penpot, Sketch, Canva, Adobe Illustrator, Adobe Photoshop, Affinity, Photopea, Inkscape, or **Other applications**. Prepare SVG + PNG files or PNG only, with an optional longest edge, padding, and transparent, white, or black background. Originals in the library stay unchanged. Canva and Photoshop default to PNG.

After **Prepare set**, preview every prepared asset. **Copy SVG set** provides a self-contained SVG grid for pasting into Figma or Sketch; original SVG artwork retains its paths, and raster sources stay raster. **Copy image** provides a single PNG grid. Clipboard grids fit each asset within 512 px; PNG grids fit within 4096 px overall. **Download set** creates a ZIP with separate prepared assets, source-page metadata, and instructions for the chosen application. Unzip it before importing the individual files. You can also drag a prepared asset into a supported webpage upload area; desktop applications use the clipboard or downloaded files.

Repeated source identities and byte-identical prepared files are removed from the set, retaining their source references. Links and non-image files are identified as excluded. Failed assets are listed individually; retry preparation or explicitly choose the ready assets before continuing. Confirmed failures are also recorded in the downloaded manifest. Preparation is limited to 100 unique assets, 64 MB of source/output data, and 8192 px / 24 million pixels per prepared file. Large clipboard sets may require downloading instead. Optional access is requested only for selected image hosts, and preparation can be cancelled. This workflow runs locally and appears only in the extension; it uses each application's clipboard or file import rather than an account connection.

Run `pnpm test:design-transfer` for built-extension checks of mixed vectors/raster images, SVG sprite/view fragments and gradients, transparency, duplicates, all destination presets, clipboard payloads, ZIP contents, converted-file dragging, denied access, failed items, cancellation, keyboard focus, and 320/390/720 px layouts. `pnpm test:design-transfer:live` also prepares public Lucide/Pillow assets and imports the generated SVG/PNG files in the real Photopea editor. Figma, Canva, and the desktop editors' live canvases require separate manual testing; the automated suite checks their export presets and payloads.

## Preview media in the sidebar

Click an album thumbnail, grid card, or list item to open its preview in a modal inside the extension. Images and icons fit without cropping; fonts show their loaded sample, and direct video and audio files have playback controls. Files and links without an inline preview show their details and a download or copy action. Album **View all** buttons still open the matching media tab.

Use **Close**, **Escape**, or click the backdrop to return to the library. Focus returns to the item you opened, and direct media playback stops when the modal closes. Preview clicks do not open a browser page. The full web library keeps its existing details pane.

Browser verification: build the extension, then run `node scripts/verify-image-actions.mjs --modal-check` to check previews, playback, dismissal, keyboard focus, failed-image recovery, and layout at 320, 390, and 720 pixels in an isolated Brave profile.

## Drag files from the sidebar

Hover over a card, list item, or album thumbnail to prepare its file, then drag it into a webpage's file input or upload drop zone. The dots button shows a spinner during preparation. For larger files, choose **Prepare for dragging** from the dots menu and wait for the ready message. Keep the sidebar open while dropping. Links and page entries drag as URLs into text fields or link-aware editors.

Images and icons use validated image bytes, with SVG sanitization and the correct file extension. Fonts, direct video/audio files, documents, stylesheets, scripts, and other downloadable files keep their original bytes. Transfers are limited to 64 MB per file, use temporary memory, and do not save a copy to disk or upload anywhere until the destination's own handler acts on the drop.

The extension relays file bytes in chunks when browser drags cross process boundaries. Its random drag capabilities expire after two minutes. Only the file being dragged is exposed; webpages cannot browse the library. Input `accept` restrictions and disabled fields are respected. Streaming playlists, protected media, unavailable files, and browser-internal pages are unsupported. Some websites require trusted native file events and may reject relayed drops; use **Download** and upload from your device there. This does not implement dragging to desktop applications.

After rebuilding, reload the extension in `chrome://extensions` or `brave://extensions`. Scan a destination tab in the open side panel before dragging to it.

Browser verification: build the extension, then run `node scripts/verify-image-actions.mjs --drag-check`. It uses an isolated Brave profile and local upload fixtures to check native dragstart/drop, file inputs, custom drop zones, URL fields, input restrictions, and byte preservation across chunked transfers.

## Library transfer

The web library stores data in browser local storage. The extension stores data in `chrome.storage.local`. Use **Export library** in one surface and **Import library** in the other to transfer a JSON archive. There is no cloud account or automatic sync in this MVP.

## Resource capture

Stashwell scans the active page and accessible frames, including open and author-created closed shadow roots exposed by Chrome, after a manual scan or during the automatic updates that action enables. It collects loaded and pending images, lazy attributes, responsive `srcset`/`picture` alternatives, inline SVGs, SVG sprite compositions, CSS backgrounds, masks, image sets and borders, pseudo-element images, and embedded files. Loaded image, script, stylesheet, font, and media requests also contribute resources when their DOM elements are gone. SVGs retain gradients, clipping, CSS styling, local definitions, and sprite placement; small SVG image elements are categorized as icons. Font icons are rendered to durable transparent PNG previews after fonts load; missing fonts are skipped. Temporary blob images are saved as durable image data. Repeated refreshes retain resource identities and bookmarks. Resource changes are debounced; captures never overlap, and unchanged snapshots do not rewrite storage. No automatic scan is authorized by merely opening the panel, granting file access, or visiting an unscanned tab.

Repeated scans of the same page keep previously found resources and saved bookmarks. Exact duplicates and unsigned resize variants share one entry; signed URLs, crop parameters, and SVG fragments remain distinct. Equivalent captured SVGs ignore accessibility labels, CSS classes, generated definition IDs, and rendered size when identifying duplicates. Imports and stored captures of the same page merge without losing unique items or bookmarks. Deduplication stays within each source page so other pages retain their resource provenance. The scanner does not impose a resource-count or 8 KB inline-SVG cutoff. The extension requests `unlimitedStorage` to retain larger collections locally. A private or protected page can only yield resources accessible to the signed-in browser session where Stashwell runs.

An image's `src`, `srcset`, lazy sources, and `picture` alternatives share one card. Alternative URLs are retained with that item so network observations, rescans, and imports cannot add them back as separate copies. Rescanning also merges older duplicate entries for those declared alternatives and preserves their bookmarks. Shared lazy placeholders do not join unrelated images.

Run `pnpm test:capture` for the capture, identity/import, automatic-update, and library-management regression suites. Run `pnpm test:capture:live` for public Excalidraw, diagrams.net, GitHub, and Lucide smoke tests, or pass your own URLs to `node scripts/verify-real-sites.mjs https://your-app.example/` after building. The live suite uses an isolated browser profile and checks observed loaded image URLs, SVG path geometry, inline icon decoding/pixels, stable IDs, resource retention, and duplicate identities across scans. It writes its latest JSON report and screenshots to `.impeccable/review/`. Set `STASHWELL_BROWSER_PATH` to a compatible Chromium browser if Brave is not installed at the default Windows path.

A scan is a snapshot, not a crawl of every route or a full application export. Scroll and open menus or screens to expose virtualized and interaction-loaded assets; automatic updates collect these while the panel remains open. Ungranted cross-origin frames, blocked or expired resources, individual objects painted only into a canvas/WebGL surface, and server-side assets the browser has never received cannot be guaranteed. Live counts change as the source applications change.

Build and run `node scripts/verify-auto-updates.mjs` to verify first-scan authorization, dynamic resources and frames, automatic loading after the first scan, visibility and tab boundaries, origin changes, stale-result cancellation, exclusions, and panel-session reset. `node scripts/verify-image-actions.mjs --scan-check` isolates the manual capture path by holding watcher notifications in the fixture; it verifies permissions, complete resource capture, deduplication, and navigation races. The automatic-update suite uses the real watcher to verify automatic collection. Headless functional fixtures pre-grant only their local host; the production package grants no hosts at installation.

## Security signals

Local checks inspect URL schemes and hostname patterns, including unencrypted HTTP, unusual schemes, credentials in a URL, encoded hostnames, direct IP hosts, known shorteners, and executable file extensions. HTTPS is reported only as transport encryption; it is not a statement that a host, redirect, page, or file is trustworthy.
