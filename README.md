# Allhere

Allhere is a local-first web resource library with a Chrome side panel. The first manual **Scan page** starts collection and automatic resource updates for that tab while the panel is visible. **Pause** stops automatic updates; **Scan again** refreshes once without clearing that pause. Unscanned tabs never collect automatically. Switching to a previously scanned tab resumes its updates within the same panel session and origin. The web library and extension use the same archive format.

## Workspace

- `apps/web` — Next.js library dashboard, using Turbopack for development.
- `apps/extension` — CSP-compatible Manifest V3 side panel, sharing the React library UI with the Next.js dashboard.
- `packages/core` — shared resource types, archive helpers, and local URL heuristics.
- `packages/library-ui` — shared Drive-inspired library interface and storage adapters.

The repo uses pnpm workspaces and Turborepo. The Next.js projects use Turbopack in development.

## Run locally

```sh
pnpm install
pnpm dev
```

The web library runs at `http://localhost:3000`; the extension preview runs at `http://localhost:3001`.

## Load the Chrome extension

```sh
pnpm --filter @allhere/extension build
```

In Chrome, open `chrome://extensions`, turn on Developer mode, choose **Load unpacked**, and select `apps/extension/out`. The extension requires Chrome 114 or later for the Side Panel API.

The extension uses a separate static React bundle because Manifest V3 blocks inline scripts generated by Next.js. Both surfaces use the same shared library UI and adapters.

Click Allhere's toolbar icon on the webpage, then choose **Scan page**. On each new tab or after navigating to another origin, invoke the toolbar icon and scan manually again. The extension uses `activeTab` for temporary access, plus `scripting`, `sidePanel`, `storage`, `unlimitedStorage`, `downloads`, and `alarms`. It adds no broad `tabs` or required host permission. Scans never request persistent website access. Optional HTTP/HTTPS grants are requested only for selected file actions; these grants alone never enable automatic collection. A packaged resource watcher runs only on a manually scanned, active tab while its panel connection is open. It observes resource-related changes, fonts, loads, and accessible shadow roots; it stops when paused, hidden, inactive, or closed. Security checks remain local.

## Manage your library

The canonical logo is `apps/extension/public/icons/allhere.svg`. After changing it, run `pnpm generate:brand` to sync the website mark, generate transparent 16/32/48/128px extension icons, and refresh the store promo artwork.

The scan button shows the active tab's favicon, with a globe fallback. Amber **Scan page** means the current document needs a scan; blue **Scan again** means it was scanned. Before the first scan, the header explains that scanning also enables automatic updates. Afterwards it shows **Auto-updates on**, **Pause**, or **Resume**. Authorization and pause state live only in memory for that tab and origin during the panel session. Library management and deleted-page exclusions hold automatic updates; background refreshes never restore deleted resources. Manual scans and imports can restore exclusions.

Open the menu at the right of **Scan page** and choose **Manage**. Search captured pages, select pages to delete, or open a page to select and delete individual items. **Undo** restores the most recent deletion while the library remains open. Deleted pages and items remain deleted when tabs change or the panel reopens. An explicit **Scan page** action restores resources from the current page; importing a page also restores it.

Choose **Saved items** from the same menu to browse bookmarks across captured pages. Images, Icons, Fonts, Video & audio, Links, Files, and **All saved** all stay filtered to bookmarks. Source-page filtering, selection, and bulk actions use that same saved scope. Choose **All resources** or **Back to library** to return to the full collection.

Browser verification: build the extension, then run `node scripts/verify-library-management.mjs`. It uses an isolated Brave profile to check saved filtering, deletion and Undo, failed writes, automatic rescan suppression, persistence, and responsive management controls. Set `ALLHERE_WEB_URL` to a running Next.js library to include the shared web interface.

## Download video and audio

Scan a page, open **Video & audio**, and use a card's dots menu to download direct video or audio files. The scanner does not extract YouTube videos. YouTube watch, Shorts, and embed URLs found on a page can still appear in **Links** with Copy URL.

Previously saved YouTube video cards remain in the library until deleted or their source page is rescanned. They show a static thumbnail and offer Copy URL. YouTube video/audio downloading is not offered.

Direct media downloads use the browser download manager. The bottom download bar shows bytes received, a percentage when known, Cancel, completed files, and failures. Expand it to see earlier downloads; completed files can be shown in their folder. Started file transfers continue when the sidebar closes, and their state restores when it reopens. The bar remains visible inside a preview modal.

If website access was withheld, the download bar shows **Allow access & retry** for the media host. Denying file-host access leaves the action available to retry. Scanning uses temporary toolbar access and has no persistent site-access menu. Host restrictions and unsupported stream playlists are reported separately. After rebuilding, reload Allhere on the browser's extensions page and reopen its sidebar to load the new controls and manifest.

Verification: `node scripts/verify-image-actions.mjs --download-check` checks direct file bytes, progress, cancellation, reload persistence, native website-access requests and simulated denial/grant/retry. It also checks that a direct video file appears in **Video & audio** while YouTube watch and Shorts URLs remain links.

## Download files and selected resources

Files with uncommon extensions are collected alongside common documents and media. In the extension, a single direct HTTP or HTTPS file download uses Chrome's download manager, which keeps the source filename from the server when available. Direct file resources are saved as received, without converting their format. Image and icon actions still validate supported preview formats. Links and page entries download as `.url` shortcuts.

Icon and image menus and sidebar previews include a **Download format** selector. Icons offer Original, SVG, PNG, JPEG, and WebP; images offer Original, PNG, JPEG, and WebP. Original is the default. SVG keeps vector icons as vectors and embeds raster icons as images. JPEG uses a white background for transparency. Converting an animated image saves one frame; Original format at Original size preserves its source format.

Images also offer **Image size: Original / 2× / 4×** in their menu, preview, and bulk actions. Original is the default. The selected factor applies to width and height and is shared between preview and download. Previews render the generated image bytes and show their output dimensions; the web details view also offers a resized download. Processing uses the browser locally, without Python, an external processing API, or an AI model. Resizing increases pixel dimensions without reconstructing missing detail. With Original format selected, enlarged exports use a PNG frame; explicit PNG, JPEG, or WebP choices keep that requested format. Enlarged filenames include `-2x` or `-4x`. Output is limited to 40 megapixels and 16,384 pixels per side, with clear errors and smaller-size recovery. Closing a preview or changing its settings cancels pending work and releases generated preview URLs.

Select resources and choose **Download as ZIP** to package them, including files with uncommon formats. The bulk actions panel has separate **Icon format** and **Image format** selectors and an **Image size** control; other files keep their original bytes. With Original format and Original size selected, the ZIP uses source filenames when supplied by the server. It gives duplicate names a suffix and lists unavailable entries in `allhere-skipped.txt`. ZIP creation is limited to 256 MB of included file data in this browser session. The web dashboard also limits an individual fetched download to 256 MB and requires the file host to allow browser cross-origin fetching. Protected links, expired addresses, and streaming playlists may require downloading from the source site.

Verification: build the extension, then run `node scripts/verify-image-actions.mjs --format-check` to check converted and 2×/4× file bytes and dimensions, transparency, icon SVGs, original preservation, size limits, mixed ZIPs, preview/export agreement, access denial/retry, cancellation, preview URL cleanup, and responsive controls. Set `ALLHERE_WEB_URL` to a running web library to include web preview/download controls and a converted ZIP.

## Preview media in the sidebar

Click an album thumbnail, grid card, or list item to open its preview in a modal inside the extension. Images and icons fit without cropping; fonts show their loaded sample, and direct video and audio files have playback controls. Files and links without an inline preview show their details and a download or copy action. Album **View all** buttons still open the matching media tab.

Use **Close**, **Escape**, or click the backdrop to return to the library. Focus returns to the item you opened, and direct media playback stops when the modal closes. Preview clicks do not open a browser page. The full web library keeps its existing details pane.

Browser verification: build the extension, then run `node scripts/verify-image-actions.mjs --modal-check` to check previews, playback, dismissal, keyboard focus, failed-image recovery, and layout at 320, 390, and 720 pixels in an isolated Brave profile.

## Drag files from the sidebar

Hover over a card, list item, or album thumbnail to prepare its file, then drag it into a webpage's file input or upload drop zone. The dots button shows a spinner during preparation. For larger files, choose **Prepare for dragging** from the dots menu and wait for the ready message. Keep the sidebar open while dropping. Links and page entries drag as URLs into text fields or link-aware editors.

Images and icons use validated image bytes, with SVG sanitization and the correct file extension. Fonts, direct video/audio files, documents, stylesheets, scripts, and other downloadable files keep their original bytes. Transfers are limited to 64 MB per file, use temporary memory, and do not save a copy to disk or upload anywhere until the destination's own handler acts on the drop.

The extension relays file bytes in chunks when browser drags cross process boundaries. Its random drag capabilities expire after two minutes. Only the file being dragged is exposed; webpages cannot browse the library. Input `accept` restrictions and disabled fields are respected. Streaming playlists, protected media, unavailable files, and browser-internal pages are unsupported. Some websites require trusted native file events and may reject relayed drops; use **Download** and upload from your device there. This does not implement dragging to desktop applications.

After rebuilding, reload the extension in `chrome://extensions` or `brave://extensions`. Scan a destination tab in the open side panel before dragging to it.

Browser verification: build the extension, then run `node scripts/verify-image-actions.mjs --drag-check`. It uses an isolated Brave profile and local upload fixtures to check native dragstart/drop, file inputs, custom drop zones, URL fields, input restrictions, and byte preservation across chunked transfers.

## Library transfer

The web library stores data in browser local storage. The extension stores data in `chrome.storage.local`. Use **Export library** in one surface and **Import library** in the other to transfer a JSON archive. There is no cloud account or automatic sync in this MVP.

## Resource capture

Allhere scans the active page and accessible frames, including open shadow roots, after a manual scan or during the automatic updates that action enables. It collects loaded and pending images, lazy image URLs, inline SVGs, distinct SVG sprite symbols, CSS backgrounds and masks, pseudo-element images, and embedded files. Font icons are rendered to durable transparent PNG previews after fonts load; missing fonts are skipped. Temporary blob images are saved as durable image data. Repeated refreshes retain resource identities and bookmarks. Resource changes are debounced; captures never overlap, and unchanged snapshots do not rewrite storage. No automatic scan is authorized by merely opening the panel, granting file access, or visiting an unscanned tab.

Repeated scans of the same page keep previously found resources and saved bookmarks. Exact duplicates and known resize variants share one entry; distinct signed URLs and SVG sprite symbols remain separate. The scanner does not impose a resource-count or 8 KB inline-SVG cutoff. The extension requests `unlimitedStorage` to retain larger collections locally. A private or protected page can only yield resources visible to the signed-in browser session where Allhere runs.

Build and run `node scripts/verify-auto-updates.mjs` to verify first-scan authorization, dynamic resources and frames, Pause/Resume, visibility and tab boundaries, origin changes, stale-result cancellation, exclusions, and panel-session reset. `node scripts/verify-image-actions.mjs --scan-check` verifies the manual/paused path, permissions, complete resource capture, deduplication, and stable rescans. Headless functional fixtures pre-grant only their local host; the production package grants no hosts at installation.

## Security signals

Local checks inspect URL schemes and hostname patterns, including unencrypted HTTP, unusual schemes, credentials in a URL, encoded hostnames, direct IP hosts, known shorteners, and executable file extensions. HTTPS is reported only as transport encryption; it is not a statement that a host, redirect, page, or file is trustworthy.
